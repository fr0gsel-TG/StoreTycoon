# StoreTycoon — система IT-событий и мини-игр v0.1

## 1. Общая идея

StoreTycoon остаётся TYCOON-игрой про развитие IT-офиса, но поверх экономики появляется второй игровой слой:

**Офис → получает специализацию → участвует в IT-событиях → игрок лично проходит короткую мини-игру → получает результат → награда усиливает дальнейшее развитие.**

Главный принцип событий:

- событие длится ограниченное время;
- на экране появляется небольшая карточка/терминал;
- игра показывает короткое IT-сообщение или ситуацию;
- ниже появляются 2–4 команды;
- игрок выбирает команду, которая лучше всего подходит для текущей ситуации;
- правильные ответы дают высокий результат;
- ошибки уменьшают качество защиты/решения и могут создавать дополнительный ущерб;
- события не должны уничтожать постоянный прогресс игрока;
- влияние офиса должно давать преимущества, но не превращать мини-игру в автоматическую победу.

Важно: команды и ситуации являются игровыми абстракциями. Они должны выглядеть как IT, но не обязаны моделировать реальное администрирование или кибербезопасность.

# 2. Единый интерфейс события

Базовый экран:

```text
┌─────────────────────────────────┐
│ ⚠ DDoS ATTACK          00:07    │
│                                 │
│  INCOMING TRAFFIC IS SPIKING    │
│                                 │
│  "UDP FLOOD DETECTED"            │
│                                 │
│  [ BLOCK ]   [ BACKUP ]         │
│  [ PATCH  ]   [ RESTART ]       │
│                                 │
│  Defense ████████░░ 82%          │
└─────────────────────────────────┘
```

Каждый раунд занимает примерно 1–4 секунды.

Цикл:

1. Ситуация появляется.
2. Запускается короткий таймер.
3. Игрок выбирает команду.
4. Игра сразу показывает микрорезультат.
5. Появляется следующая ситуация.
6. По окончании события считается итоговый score.

---

# 3. Общая модель результата

У события есть:

- Base Difficulty — сложность;
- Time Limit — время на один ответ;
- Accuracy — точность ответов;
- Speed — скорость реакции;
- Streak — серия правильных ответов;
- Severity — тяжесть проблемы;
- Office Bonuses — бонусы от комнат/предметов.

Пример итогового score:

**Score = Accuracy × 0.6 + Speed × 0.25 + Streak × 0.15**

При этом конкретная формула может быть другой в зависимости от режима.

Результат лучше показывать не только цифрой:

```text
EXCELLENT
Accuracy: 96%
Reaction: 91%
Streak: x8
Damage Prevented: 94%
```

# 4. Событие: DDoS Attack

## Суть

Офис получает волну подозрительного трафика.

Игроку показываются короткие сообщения:

```text
"TRAFFIC SPIKE"
"UDP FLOOD"
"REQUEST STORM"
"SERVER UNDER LOAD"
```

Варианты команд:

```text
[ BLOCK ]
[ FILTER ]
[ RESTART ]
[ BACKUP ]
```

Правильная команда зависит от ситуации.

## Примеры

```text
"UDP FLOOD"
→ FILTER

"KNOWN ATTACK SOURCE"
→ BLOCK

"SERVER UNDER EXTREME LOAD"
→ LIMIT

"TRAFFIC PATTERN NORMALIZED"
→ MONITOR
```

## Ошибка

Неверная команда не обязательно сразу заканчивает событие.

```text
Correct → -0 damage
Near-miss → -3 damage
Wrong → -8 damage
Critical mistake → -15 damage
```

## Таймер

На одном этапе:

- Easy: 3.0 sec
- Normal: 2.2 sec
- Hard: 1.5 sec
- Expert: 1.0 sec

## Влияние офиса

Security Room:

- увеличивает допустимое количество ошибок.

Server Room:

- уменьшает ущерб от одной ошибки.

Network Infrastructure:

- добавляет небольшой бонус к времени.

## PvP

Игрок A запускает DDoS-атаку на защищающегося игрока B.

Сила атаки определяется подготовкой атакующего.

Например:

```text Attack Power: 72
```

Игрок B проходит мини-игру.

Результат:

```text Defense: 91%
Final Damage: 6%
```

Постоянные деньги и комнаты не уничтожаются. PvP лучше использовать для временных эффектов, рейтинга и специальных наград.

# 5. Событие: Hacker Intrusion

## Суть

В офисе обнаруживается серия подозрительных подключений.

На экране:

```text
"SUSPICIOUS LOGIN"
```

Появляется 3–4 варианта:

```text
[ ALLOW ]
[ BLOCK ]
[ VERIFY ]
[ IGNORE ]
```

Иногда правильный ответ неочевиден.

## Примеры

```text
"UNKNOWN DEVICE + KNOWN USER"
→ VERIFY

"REPEATED FAILED LOGIN"
→ BLOCK

"AUTHORIZED DEVICE"
→ ALLOW

"STRANGE LOCATION"
→ VERIFY
```

## Особенность

В этом событии скорость важна, но слишком быстрые решения повышают риск ошибки.

Можно ввести скрытую механику:

**Quick Decision Bonus**

Игрок должен одновременно быть быстрым и внимательным.

# 6. Событие: Database Failure

## Суть

Произошёл сбой базы данных.

Сообщения:

```text
"DATABASE UNAVAILABLE"
"DATA CORRUPTION"
"CONNECTION LOST"
"BACKUP AVAILABLE"
```

Команды:

```text
[ RESTORE ]
[ RESTART ]
[ BACKUP ]
[ IGNORE ]
```

## Основная механика

Здесь важна не только правильность, но и порядок действий.

Например:

```text
CORRUPTION DETECTED
→ STOP WRITE

BACKUP FOUND
→ VERIFY

BACKUP VERIFIED
→ RESTORE
```

Можно сделать 2–3 шага подряд.

Таким образом событие становится небольшим логическим пазлом.

# 7. Событие: Malware Scan

## Суть

В системе обнаружены подозрительные процессы.

На экране появляется один главный объект:

```text
"UNKNOWN PROCESS DETECTED"
```

И несколько действий:

```text
[ SCAN ]
[ DELETE ]
[ ALLOW ]
[ ISOLATE ]
```

## Механика

Сначала игрок должен определить, насколько серьёзна ситуация.

Пример:

```text
"UNKNOWN PROCESS — NO NETWORK ACCESS"
→ SCAN

"PROCESS MODIFIES SYSTEM FILES"
→ ISOLATE

"MALICIOUS SIGNATURE CONFIRMED"
→ DELETE
```

## Ошибка

Преждевременное удаление может дать небольшой штраф, но не критический.

# 8. Событие: Server Overload

## Суть

Сервера перегружены.

На экране несколько машин:

```text
SERVER 01  ██████████  96%
SERVER 02  ████        34%
SERVER 03  ██████      57%
```

Появляется команда:

```text
"REDISTRIBUTE LOAD"
```

Варианты:

```text
[ SERVER 01 ]
[ SERVER 02 ]
[ SERVER 03 ]
```

Игрок должен выбрать менее загруженный сервер.

## Сложность

На высоких уровнях показатели меняются прямо во время выбора.

Таким образом игроку приходится быстро следить за состоянием.

## Офис

Server Room даёт:

- больше серверов;
- больше времени;
- меньше штраф за неправильное распределение.

# 9. Событие: Encryption Breach

## Суть

Поступает подозрительный запрос на защищённые данные.

Примеры:

```text
"KEY COMPROMISED"
"UNAUTHORIZED REQUEST"
"SECURE CHANNEL FAILED"
```

Команды:

```text
[ ROTATE KEY ]
[ BLOCK ]
[ VERIFY ]
[ IGNORE ]
```

## Особенность

Иногда правильный ответ состоит из двух действий:

```text
KEY COMPROMISED
→ ROTATE KEY

UNKNOWN ACCESS
→ BLOCK
```

Это позволяет постепенно вводить цепочки.

# 10. Событие: Deployment Failure

## Суть

Новая версия продукта почти готова к запуску, но возникла проблема.

Сообщения:

```text
"BUILD FAILED"
"TEST FAILED"
"DEPLOYMENT READY"
"VERSION MISMATCH"
```

Команды:

```text
[ ROLLBACK ]
[ RETRY ]
[ TEST ]
[ DEPLOY ]
```

Примеры:

```text
"TEST FAILED"
→ ROLLBACK / FIX

"BUILD FAILED"
→ RETRY

"ALL TESTS PASSED"
→ DEPLOY
```

## Хорошая особенность

Игрок может рискнуть.

Например:

```text
"1 TEST FAILED"
```

Можно:

- отменить релиз;
- повторить;
- рискнуть и продолжить.

Рискованный вариант иногда может принести больше награды, но при ошибке штраф выше.

# 11. Событие: Data Leak

## Суть

Есть риск утечки данных.

На экране:

```text
"UNUSUAL DATA TRANSFER"
```

Команды:

```text
[ BLOCK ]
[ TRACE ]
[ ALLOW ]
[ REPORT ]
```

Здесь важно различать:

- источник;
- канал;
- объект;
- нормальный или подозрительный трафик.

## Механика

Сначала игрок может выбрать:

**TRACE**

а затем получает второй экран:

```text
SOURCE FOUND
"UNKNOWN EXTERNAL NODE"
```

и выбирает:

**BLOCK**.

Так создаются короткие двухходовые мини-сценарии.

## Суть

Часть офиса теряет соединение.

На экране:

```text
NETWORK NODE 01  ✅
NETWORK NODE 02  ❌
NETWORK NODE 03  ✅
```

Команды:

```text
[ RESTART NODE ]
[ CHECK ROUTE ]
[ SWITCH ]
[ IGNORE ]
```

## Механика

Игрок должен найти проблемный участок.

На высоком уровне одновременно появляются:

- несколько неисправных узлов;
- ограниченное время;
- ложные сигналы.

В офисном AI-сервисе произошло отклонение.

```text
"MODEL RESPONSE ANOMALY"
"ACCURACY DROP"
"TRAINING ERROR"
```

Команды:

## Особенность

Это более позднее событие.

→ MONITOR

# 14. Общий прогресс сложности

Нужно избегать простого:

**больше скорость = больше сложность.**

Лучше развивать сразу несколько параметров.

## Level 1

2–3 команды.

Ситуация очевидная.

3 сек на ответ.

## Level 2

4 команды.

2.5 сек.

Появляются близкие по смыслу варианты.

## Level 3

2.0 сек.

Появляются цепочки из 2 шагов.

## Level 4

1.5 сек.

Ситуация меняется во время раунда.

## Level 5

1.0–1.2 сек.

Несколько угроз одновременно.

## Elite

Комбинация разных событий:

```text DDoS + Database + Network
```

Игрок должен быстро переключаться между типами проблем.

# 15. Boss Fight: Mega Bug

## Концепция

Это не обычное событие, а 30–90-секундная битва.

Босс:

```text
🐛 MEGA BUG
HP ████████████████████
```

Игрок последовательно решает задачи.

Раунд 1 — найти проблему.

Раунд 2 — выбрать действие.

Раунд 3 — исправить.

Раунд 4 — проверить.

Раунд 5 — выпустить фикс.

Каждый правильный ответ снимает HP босса.

Ошибки восстанавливают HP или уменьшают время.

## Визуально

На фоне можно показывать офис:

- сотрудники бегают к нужной комнате;
- мониторы краснеют;
- серверы мигают;
- после успешного фикса офис возвращается в норму.

# 17. Boss Fight: System Meltdown

Это самый хаотичный режим.

Одновременно:

- сервер перегружен;
- база падает;
- сеть нестабильна;
- появляется подозрительный процесс.

Игроку постоянно показываются новые проблемы.

Необходимо выбирать:

**какая проблема сейчас наиболее опасна.**

Это уже не только реакция, но и приоритизация.

# 19. PvP: асинхронный Cyber Battle

Игроки не обязаны находиться онлайн одновременно.

Игрок A формирует атаку:

```text
Attack Type: DDoS
Power: 81
```

Система отправляет её игроку B.

Игрок B позже заходит и видит:

```text
⚠ RIVAL ATTACK

Rival: PixelLabs
Threat: DDoS

DEFEND
```

Он проходит мини-игру.

Результат:

```text
Perfect Defense
→ 0% effect

Good Defense
→ weak temporary effect

Failed Defense
→ stronger temporary effect
```

Важно:

**основной прогресс офиса не уничтожается.**

PvP лучше награждать через:

- рейтинг;
- Battle Points;
- сезонные награды;
- уникальный декор;
- временные бусты.

# 20. Система Streak

Правильные ответы подряд:

```text
x1
x2
x3
x4
x5
```

На x5:

**+5% score**

На x10:

**+10% score**

Ошибка сбрасывает streak.

Можно добавить визуальный эффект:

```text
PERFECT STREAK
x8
```

Но не следует делать бонус настолько большим, чтобы одна ошибка полностью разрушала весь забег.

---

# 21. Система "Near Miss"

Очень важная вещь для ощущения справедливости.

Не все ошибки одинаковы.

Например:

Правильно:

```text BLOCK
```

Игрок нажал:

```text VERIFY
```

Система может считать это:

**Near Miss**

И дать небольшой штраф.

Это особенно полезно на высоких уровнях.

---

# 22. Защита от угадывания

Если игрок просто запомнит:

> DDoS = BLOCK

игра быстро станет скучной.

Поэтому команды нельзя привязывать к одному слову.

Примеры:

```text "KNOWN MALICIOUS SOURCE"
→ BLOCK

"UNKNOWN SOURCE, NORMAL ACTIVITY"
→ VERIFY

"TRAFFIC SPIKE, MANY REQUESTS"
→ FILTER

"SERVER RESPONSE DEGRADED"
→ LIMIT
```

То есть игрок должен читать смысл всей фразы.

# 23. Генерация контента

Каждое событие должно иметь библиотеку:

```text Situation
Correct Answer
Alternative Answers
Difficulty
Severity
Time Limit
Event Type
```

Например:

```text
{
  "event": "ddos",
  "text": "UDP FLOOD DETECTED",
  "correct": "FILTER",
  "alternatives": ["BLOCK", "RESTART"],
  "difficulty": 2,
  "severity": 3
}
```

Таким образом можно создавать сотни ситуаций без переписывания самой мини-игры.

Комнаты и предметы не должны просто давать огромный бонус к мини-играм.

Лучше использовать маленькие преимущества:

Security Room:
+5–10% defense window

Server Room:
+1 ошибка без серьёзного штрафа

QA Room:
+ немного времени

AI Lab:
1 подсказка за событие

Meeting Room:
+ bonus к командным событиям

Development Room:
+ bonus к Hackathon

Так игрок ощущает:

**"Я построил этот офис — и теперь он реально помогает мне."**

# 25. Система подсказок

Для новичков:

```text 💡 HINT

Look at the source.
```

Для опытных игроков подсказки не нужны.

Подсказка может:

- убрать один неправильный вариант;
- добавить 0.5 сек;
- показать ключевое слово.

Но использование подсказки уменьшает итоговый score.

# 26. Система наград

Не надо давать только деньги.

Категории наград:

**Economic**
- деньги;
- временный доход.

**Progression**
- Battle Points;
- Event XP.

**Visual**
- неон;
- серверные стойки;
- голограммы;
- редкая мебель;
- анимации.

**Prestige**
- титулы;
- рамки;
- значки;
- специальные эффекты.

Особенно сильны визуальные награды, потому что игрок сможет показывать их в своём офисе.

# 27. Что должно происходить после полного прокачивания офиса

Когда игрок уже открыл все базовые комнаты, события становятся следующим слоем прогрессии.

Например:

```text OFFICE LEVEL
      ↓
EVENT LEVEL
      ↓
BATTLE RANK
      ↓
ELITE EVENTS
      ↓
BOSS FIGHTS
      ↓
CHAMPIONSHIP
```

То есть заканчивается один тип прогресса, но открывается другой.

# 28. Главный принцип всей системы

Мини-игра должна быть:

**короткой → понятной → визуально насыщенной → немного стрессовой → честной → связанной с офисом.**

Идеальная длительность обычного события:

**10–30 секунд**

Boss Fight:

**30–90 секунд**

Олимпиада:

**2–5 минут**

PvP-сражение:

**30–90 секунд**

Так игрок может зайти, быстро провести событие и снова вернуться к строительству/развитию офиса.

# 30. Финальная концепция

StoreTycoon может иметь три взаимосвязанных слоя:

### TYCOON
Строительство и развитие офиса.

### EVENTS
Короткие временные IT-инциденты.

### COMPETITION
PvP, олимпиады и Boss Fights.

Ключевая мини-игра:

**появляется короткое сообщение → игрок анализирует ситуацию → выбирает одну из команд → получает мгновенный результат → переходит к следующей задаче.**

Таким образом игрок не просто смотрит, как растёт доход.

Он периодически становится **оператором собственного IT-офиса** и лично спасает его от проблем, участвует в соревнованиях и сражается с системными боссами.
